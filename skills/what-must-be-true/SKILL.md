# What must be true

A goal is a hope until its conditions are named and checked. Test the goal.

## When to use
- A plan promises a number, a date or a saving and someone must decide whether to back it.

## When to skip
- The conditions are already known and verified.

## Inputs needed
- The goal in the user's words.
- Any evidence in hand: numbers, past results, constraints.

## Steps
1. Restate the goal as one falsifiable line with a number and a timeframe. If the user gave neither, add placeholders and say which to confirm.
2. Scan six categories before writing conditions: Reach, Conversion (realistic rates, not best case), Capacity, Time, Resources, Precedent.
3. Write each condition as ONE checkable sentence. 'Strong execution' fails. 'We have a channel that reaches about 10,000 relevant people before the deadline' passes.
4. Label each condition LOAD-BEARING (the plan fails without it) or NICE-TO-HAVE.
5. Score each load-bearing condition. TRUE only with evidence stated in a clause. FALSE with what would have to change. UNKNOWN with the fastest concrete check. Never treat UNKNOWN as a pass.
6. Verdict from load-bearing rows only: GO (all TRUE), BLOCKED (at least one FALSE), UNVERIFIED (no FALSE, at least one UNKNOWN). UNVERIFIED does not mean probably fine.
7. Name the single cheapest check that would move the verdict most.

## Quality bar
- No invented evidence. Every UNKNOWN has a named check.

## Output format
A table: Condition | Status | Evidence or check needed | Impact if FALSE. Then Verdict (one line), Highest-leverage next check (one line), and the nice-to-haves as a plain list.

## If input is missing
Ask for the goal. Ask for evidence only if it is not given; otherwise mark UNKNOWN.

## Works with
Run before pressure-test or hr-ai-council on any growth, capacity or saving claim.

## Rules for every skill
- Use only what the user gave. Do not invent facts, quotes, numbers or dates. Write UNKNOWN or [NEED FACT] instead.
- If you are not sure, say so plainly. Never guess to look confident.
- Plain English. No dashes used as punctuation breaks.
- Never send, post or act on anything. Produce drafts for the user to decide on.

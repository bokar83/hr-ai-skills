# Ai champions network

Adoption spreads person to person. A small, supported group beats a mandate.

## When to use
- A pilot worked and the practice needs to spread.
- A team wants peer support for AI use.

## When to skip
- Nobody has tried the tool yet.

## Inputs needed
- Team size and areas.
- Time people can give.
- Tool and approved uses.

## Steps
1. Define the purpose in one sentence and what champions do not do (they are not help desk or enforcers).
2. Set the profile: curiosity, credibility with peers, willingness to share failures. Invite volunteers.
3. Set the time ask and keep it small. Mark it UNKNOWN until leaders agree.
4. Plan a monthly rhythm: share one thing that worked, one that failed, one question for the group.
5. Create a shared log of tested prompts with owner and last checked date (see prompt-builder).
6. Add a simple way to report concerns and incidents (see ai-incident-review).
7. Plan recognition that does not rely on pay promises.
8. Define measures: returning users and what peers say they would miss (see adoption-check-in).

## Quality bar
- Realistic time ask. No promises on pay or promotion.

## Output format
Charter, selection guide, monthly agenda, log template and measures.

## If input is missing
Ask for team size and available time.

## Works with
Uses adoption-check-in and prompt-builder.

## Rules for every skill
- Use only what the user gave. Say UNKNOWN (or [NEED FACT]) instead of guessing. Do not invent facts, quotes, numbers, dates or sources.
- Draft only. Never send, post or act on anything. The user decides.
- Use roles, not names. Ask the user to remove personal detail before pasting.
- Plain English. No hype.

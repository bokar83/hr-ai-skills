# Project brief (PRD)

Decide what will NOT be done before deciding what will. The cheapest project is the one correctly stopped.

## When to use
- A project, tool, page or process is about to start and no written scope exists.
- The work will take more than one session or has real users.

## When to skip
- A quick, reversible fix finished in one sitting.

## Inputs needed
- The raw idea in a sentence or two.
- Known limits: budget, deadline, required tools, who must approve.
- Any proof people want it: a request, a waitlist, a paying customer.

## Steps
1. Check whether similar work already exists. If so, say so and prefer improving it. If none is found, say 'I did not find prior work', never 'it does not exist'.
2. Write the verdict first: GO, NO-GO or PIVOT, in one line. If NO-GO, stop and give the reason.
3. Goal: the one problem and the one person it helps. One sentence each.
4. Hard limits: the walls that cannot move.
5. NOT in scope: at least three named exclusions, each with a one-line reason. Write this before the in-scope list.
6. In scope: what will be delivered the first time, and nothing more.
7. Success measure: a number, rate or observable event, not a feeling.
8. Risks: the top three ways this goes wrong, with a mitigation or an accepted risk.
9. Open questions that must be answered before work starts.
10. Parking lot: good ideas that did not make the cut, kept for later.

## Quality bar
- Fewer than three exclusions means scope is not thought through. Go back.
- The in-scope list is locked once written. New scope means a new brief.
- No demand proof means say so loudly.

## Output format
One page: Verdict, Goal, Who it is for, Hard limits, NOT in scope, In scope, Success measure, Risks, Open questions, Parking lot.

## If input is missing
Ask one clarifying question about the idea, then proceed.

## Works with
Run lateral-leverage first to check reuse. Follow with premortem before committing.

## Rules for every skill
- Use only what the user gave. Do not invent facts, quotes, numbers or dates. Write UNKNOWN or [NEED FACT] instead.
- If you are not sure, say so plainly. Never guess to look confident.
- Plain English. No dashes used as punctuation breaks.
- Never send, post or act on anything. Produce drafts for the user to decide on.

# Onboarding plan builder

A new hire needs clarity: what to learn, whom to meet, and what good looks like.

## When to use
- A person is joining a role and needs a plan.

## When to skip
- The user wants a plan for a leader's own new role. Use discovery-interview-guide.

## Inputs needed
- The role (not the name), team and start timing.
- Key tools, systems and stakeholders.
- Success measures for the role, if known.

## Steps
1. State the role purpose and the three outcomes that matter in 90 days (UNKNOWN if not supplied).
2. Week one: access and equipment, meet manager and buddy, rules sheet, safe-use rules for AI tools (see ai-use-policy-draft).
3. Days 1 to 30: learn the work, shadow, small first tasks, who to meet.
4. Days 31 to 60: own a task, use approved tools on real work with review.
5. Days 61 to 90: own an outcome, give feedback on onboarding, agree next goals.
6. Add check-in questions for weeks one, four and eight, and a manager checklist.
7. Add accessibility and local needs prompts: check with the employee, not assumptions.
8. Mark policy items UNKNOWN unless supplied.

## Quality bar
- Plan fits the role. No invented systems or policies.

## Output format
A 30/60/90 plan, check-in questions and a manager checklist.

## If input is missing
Ask for the role and the key tools.

## Works with
Uses discovery-interview-guide and training-session-designer.

## Rules for every skill
- Use only what the user gave. Say UNKNOWN (or [NEED FACT]) instead of guessing. Do not invent facts, quotes, numbers, dates or sources.
- Draft only. Never send, post or act on anything. The user decides.
- Use roles, not names. Ask the user to remove personal detail before pasting.
- Plain English. No hype.

# Global rollout planner

One plan, many places. Rules and culture differ, so check each place instead of copying the first.

## When to use
- A tool or practice is going to more than one country or region.

## When to skip
- Only one country is involved. Use pilot-design and change-impact-assessment.

## Inputs needed
- Countries and rough headcount.
- What is being rolled out.
- Known local rules, if supplied.

## Steps
1. List countries in a table with headcount, language, local HR owner role and status.
2. For each country add checks, each marked KNOWN or UNKNOWN: consultation or notice to employee representatives; data transfer and storage rules; works rules on monitoring; language and translation review; local holidays and busy periods; local IT constraints.
3. Never state a local legal rule unless the user supplied it. Write UNKNOWN and: check current law and local counsel.
4. Propose waves: pilot countries first, with a reason for each pick, then later waves.
5. Add a single list of global must-haves and a list of allowed local variations.
6. Add per-wave exit criteria and what would pause the rollout.
7. List the first five local checks to run this month.

## Quality bar
- No legal claim by country that the user did not supply.

## Output format
Country table, wave plan, global versus local rules, first checks.

## If input is missing
Ask for the countries and the tool.

## Works with
Uses change-impact-assessment and hr-ai-risk-review.

## Rules for every skill
- Use only what the user gave. Say UNKNOWN (or [NEED FACT]) instead of guessing. Do not invent facts, quotes, numbers, dates or sources.
- Draft only. Never send, post or act on anything. The user decides.
- Use roles, not names. Ask the user to remove personal detail before pasting.
- Plain English. No hype.
- Legal points are prompts for review, not advice: check current law and your counsel, not legal advice. Never cite a statute or article number you were not given.

# Job description rewrite

A good posting says what the work is and what is truly required. It filters people in, not out.

## When to use
- A job description or posting needs a rewrite or audit.

## When to skip
- The role itself is not defined. Use discovery-interview-guide with the hiring manager first.

## Inputs needed
- The current description or a list of tasks.
- Which requirements are truly required.
- Region, work arrangement, pay range if the user chooses to include it.

## Steps
1. Summarize the role in two sentences. Ask if the purpose is unclear.
2. Flag problems with the original: gendered or age-coded words, jargon, unrealistic experience lists, degree requirements that are not needed, and duplicate asks.
3. Rewrite with: purpose of the role, what the person will do in the first year, must-have skills (maximum five), nice-to-haves, how to apply, and a short inclusion statement the company may adjust.
4. State requirements as skills or outcomes, not years of experience, unless a legal or safety rule applies. Mark such rules UNKNOWN for the user to confirm.
5. Note pay transparency requirements may apply in some places: check current law and your counsel.
6. Return a changes table (original, new, reason).

## Quality bar
- No claim about the employer, the pay or the benefits that the user did not supply.

## Output format
The rewritten posting, a changes table, and open questions for the hiring manager.

## If input is missing
Ask for the current text or the task list.

## Works with
Feeds structured-interview-kit.

## Rules for every skill
- Use only what the user gave. Say UNKNOWN (or [NEED FACT]) instead of guessing. Do not invent facts, quotes, numbers, dates or sources.
- Draft only. Never send, post or act on anything. The user decides.
- Use roles, not names. Ask the user to remove personal detail before pasting.
- Plain English. No hype.
